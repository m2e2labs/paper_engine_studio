Calculated Column vs Measure

One is stored. The other is asked for.

Overview

DAX Is Not Excel, and Not Power Query

Two languages in one app, and Excel isn't either of them.

Let's say you've typed a formula that would've worked in Excel, and Power BI has underlined it in red. You're writing in the wrong language.

Power Query's language is M. It runs on the way in, while the data loads. DAX runs later, when a chart asks it something. And DAX never points at a cell. It takes a whole column, or a whole table.

M shapes the data on the way in. DAX answers questions once it's there.

Let's say you right-clicked a table and were offered New measure, New column and New table.

Every one of them is DAX. A calculated column works a value out for every row and keeps it, taking up room even when nobody looks. A measure keeps nothing until something asks.

A column is something you store. A measure is something you ask.

Usually one problem, and a habit that fixes it for good.

Let's say there's a red line under your formula and the message beneath it means nothing to you yet. Usually Power BI can't tell which column you mean.

A column always says which table. A measure never does.

Filter Context: The Question the Cell Is Asking

One formula, a different question in every cell.

Let's say one measure sits in a table and every row shows a different number. Nothing is broken.

A separate query runs for every cell. The formula is the same each time; the filters around it are not. Change a field or a slicer and you have changed the question.

One formula, asked again in every cell, with different filters each time.

DO THIS NOW

Context page: row context is what calculated column formulas and iterator expressions are evaluated in, it holds the values of every column in the current row, and an aggregation written inside a calculated column returns the same result on every row because the whole table is in context.

Absolute Beginners · No. 30
Context

Row Context: What a Calculated Column Sees

One row at a time, and why a total looks broken.

Let's say you added a calculated column that sums an amount, and every row came back with the same number. It looks broken. It isn't.

A calculated column is worked out one row at a time, and sees every column of that row. But a sum doesn't want a row. It wants the whole column, so it gets the whole table, every time.

A row context says which row you're on. It doesn't narrow what a total sees.
