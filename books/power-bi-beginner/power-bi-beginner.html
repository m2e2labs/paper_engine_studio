Power Query

Combining Two Queries: Append vs Merge

Stacking rows is different from lining up columns.

Let's say you have two related tables and aren't sure which button joins them. Append stacks tables with the same columns into one longer table, like January's sales under February's. Merge lines two tables up side by side, matched on a shared column, like sales next to targets.

More rows of the same thing is Append. More columns about the same thing is Merge.

DO THIS NOW

Ask yourself which you need before you click either button: more rows, or more columns.

Fact Tables and Dimension Tables

One holds events. The others describe them.

Let's say you have a transactions table and a lookup table and you're not sure which is which. A fact table holds the events, one row per sale, with a number attached. The dimension tables around it hold the describing words, like product names or dates, that you use to slice those numbers.

Facts are the things that happened. Dimensions describe them.

Power BI for Absolute Beginners · No. 12
Modeling

Calculated Column vs Measure

One is stored. The other is asked for.

Let's say you're about to write your first formula and aren't sure which kind to pick. A calculated column computes once per row when data refreshes, and that answer sits stored in the table. A measure computes on the spot, using whatever filters are active right now, and it's never stored.

If the answer changes with the filters, it's a measure. If not, a column will do.

DO THIS NOW

Ask if the answer should change when a slicer changes. If yes, make it a measure.

What DAX Actually Is

If you've written an Excel formula, this will feel familiar.

Your First Measure: A Simple SUM

The smallest useful measure there is.

Total Sales = SUM(Sales[Amount]) adds up one column, across whatever rows are in view. Type the equals sign, start typing SUM, and pick it from the list. Add the column in brackets, and you have a working measure.

Table, then column in square brackets. That pattern carries you a long way.

CALCULATE and the Filter Context

Changing the filters a measure sees before it runs.

Let's say a measure needs a filter of its own, like "sales, but only this region." CALCULATE reruns your calculation under a different set of filters than what's normally applied. Filter a column that's already filtered elsewhere, and yours replaces that filter rather than stacking on top.

CALCULATE adds a filter, or swaps out the one already on that column.

Practice: First DAX

A sum, a filter, a count and a divide. Match the numbers.

Total Sales = SUM(Sales[Amount]) in a card: 116,922 with nothing selected. Anything else means a filter is on.

West Sales = CALCULATE([Total Sales], Sales[Region] = "West"): 27,787. Add a Region slicer, pick North. West Sales doesn't move.
